# Skill: write-prd — инструкция для аналитика

## Что это

Скилл оформляет идею фичи в полноценный PRD за несколько итераций с Claude.
Задаёт вопросы по бизнес-контексту, исследует кодовую базу, генерирует PRD
по шаблону и сохраняет его в `docs/requirements/draft/` с заготовкой PR.
Отдельным режимом — переводит готовый draft в `ready/` после ревью.

## Когда использовать

**Да:**
- Появилась идея новой фичи или продуктового изменения — нужно оформить.
- Готовый draft PRD прошёл ревью — нужно перевести в `ready/`.

**Нет:**
- Баг-репорт, хотфикс, чистый рефакторинг без продуктовых импликаций.
- Идея ещё не сформирована — сначала подумай в свободной форме,
  потом запускай скилл.

## Как запустить

В Claude Code (открытом в корне `final-example`) опиши идею своими словами:

> Хочу добавить массовый экспорт инвойсов в CSV. Напиши PRD.

Триггер-фразы: «let's add X», «what if we», «I want to introduce»,
«spec out», «draft requirements», «write a PRD» — и их русские аналоги
(Claude поймёт по контексту).

Для перевода в ready:

> Переведи PRD по bulk export в ready.

## Как идёт диалог

1. **Sources (опционально).** Скилл спросит, есть ли источники:
   транскрипты, диаграммы, мокапы, тикеты. Прикрепи или ответь `skip`.

2. **Discovery — 7 вопросов, по одному за раз:** problem, current
   workaround, hypothesis, target users, success metric, scope &
   non-goals, constraints. Если на какой-то нет ответа — отвечай `скип`
   и иди дальше. На расплывчатый ответ скилл задаст ровно один
   уточняющий, потом примет как есть.

3. **Codebase exploration.** Скилл сам пройдётся по коду, покажет
   summary из четырёх блоков (reuse / add / constraints / open
   questions). Подтверди или поправь — только после этого пишется PRD.

4. **PRD generation + git.** Сгенерирует markdown, предложит создать
   ветку и draft PR. Без твоего «yes» / «go» ничего в git не уходит.

## Что ты получишь

- Файл `docs/requirements/draft/YYYY-MM-DD-<slug>.md` со структурой
  из 9–10 секций.
- Ветка `prd/<slug>` в форке.
- Draft PR с заголовком `Draft PRD: <feature name>`.

PRD всегда на английском, независимо от языка диалога — конвенция,
не меняется.

## Перевод draft → ready

Скилл сделает 4 проверки и предложит workflow:

1. В файле не осталось маркеров `Assumption — to confirm` и
   `Skipped during discovery`.
2. Все open questions закрыты.
3. Draft PR апрувнут.
4. Меняется `Status: draft` → `ready`, файл переезжает
   через `git mv` в `ready/`, открывается обычный (не draft) PR
   с веткой `promote/<slug>`.

Если что-то не закрыто — скилл остановится и попросит сначала
поправить PRD.

## Советы и грабли

- **Описывай идею в свободной форме.** Не пытайся структурировать
  заранее — скилл сам спросит то, что нужно. Если уже есть
  структурированный бриф — он просто пропустит часть вопросов.

- **Прикладывай источники в Step 0, а не потом.** Если транскрипт
  всплывёт в середине discovery — придётся переписывать ответы,
  на которые он влияет.

- **Поправляй на этапе mirror-back.** Скилл показывает «вот что я
  уже услышал из твоего описания» перед тем, как задавать вопросы.
  Это твой шанс скорректировать до того, как ошибка попадёт в PRD.

- **Не бойся `скип`, но помни:** скипнутые вопросы — это блокер для
  перевода в `ready/`. К ним придётся вернуться.

- **Domain-термины уточняются.** Если ты пишешь на русском «счёт»,
  «клиент», «отчёт» — скилл переспросит, какой именно сущности из
  кода это соответствует. Не игнорируй эти вопросы — они защищают
  от рассинхрона PRD с реальной кодовой базой.

- **`git add` точечный, источники в репо не уезжают.** Скилл
  добавляет в коммит только сам PRD-файл. Транскрипты и мокапы
  упоминаются в §10 Sources только по метаданным.
